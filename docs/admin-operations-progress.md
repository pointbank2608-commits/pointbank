# 관리자 시스템 개선 진행 기록 (2026-10-18)

목표: 운영자 한 명이 선생님·원장 계정 1만 개를 다룰 수 있게 반복 작업은 자동화하고, 사람이 판단할 일만 "오늘 할 일"에 올린다.
이 문서는 **실제로 만든 것 / 확인한 방법 / 확인하지 못한 것 / 외부 설정이 필요한 것**을 구분해서 적는다.

> **이번 작업의 제약(그대로 지켰다)**: 배포하지 않았다 · 실제 메시지를 보내지 않았다 · 결제·환불을 실행하지 않았다 ·
> 운영 DB에 SQL을 적용하지 않았다(임시 DB에서만) · 운영 데이터를 바꾸거나 지우지 않았다 · 선생님용 기능(수업·게임·인쇄·출석)은 건드리지 않았다.
> 관리자용 서버 함수는 모두 `is_platform_admin()`을 서버에서 검사하고, 결제 웹훅·발송 대기열 같은 시스템용 함수는 `service_role`만 실행할 수 있다(메뉴를 숨기는 것만으로 막지 않는다. 비관리자 호출이 거절되는지는 임시 DB 테스트로 확인).

### Edge Function / 클라이언트
- `charge-subscriptions`·`_shared/portoneCharge.ts`·`register-billing-key`: 결정적 결제 번호, KST 날짜, 중복 청구 건너뜀, 성공 시 `plan_source = 'subscription'`.

- `lib/errorReporter.ts`: localhost·개발 서버에서 나는 오류는 운영 오류 목록으로 보내지 않는다.

## 5. `/games/lightning` 오류 조사

운영 오류 기록을 읽을 수 없어(운영 DB 미접속) **재현·원인 확정을 하지 못했다.** 코드에서 확인한 사실과 가설만 적는다.
- 개발 서버(localhost) 세션의 오류가 운영 `client_errors`로 전송되고 있었다. 핫 리로드 중 일시적인 오류가 운영 목록에 섞였을 **가능성**이 있다(증명하지 못함). → `errorReporter.ts`가 localhost·DEV에서는 전송하지 않도록 고쳤다.
- 오류 기록은 삭제하지 않았다. 이제 같은 오류가 묶여 보이고 "해결 이후 다시 발생"이 표시된다. 배포 후 같은 지문이 계속 쌓이면 실제 사용자 오류이므로 스택(시스템 상태 > 자세히)으로 이어서 조사한다.

## 6. 적용 순서와 되돌리기 (운영자가 직접)

1. **먼저 `supabase/086a` → `086b` → … → `086u` 를 알파벳 순서로 하나씩** SQL 편집기에서 실행하고 `086_check.sql`로 확인한다.
   - ⚠ `082c`(관리자 2단계 인증 서버 강제)는 이 작업과 무관하다. **인증 앱을 등록하기 전에는 실행하지 말 것**(등록 전에 켜면 관리자 화면이 막힌다).
   - ⚠ SQL 편집기에 약 3KB 넘게 붙여 넣으면 잘리는 문제가 이전에 있었다(CLAUDE.md 072 항목). 이번 파일은 4~7KB라 **잘리면 "unterminated dollar-quoted string" 오류**가 난다. 그 경우 함수 하나 단위로 나눠 실행하거나 Supabase CLI·psql로 파일째 실행한다. 임시 DB에서는 20개 파일 전부 통과했다.
2. SQL 적용 후 앱을 배포한다(앱은 086 전에도 켜지지만 새 화면은 "불러오지 못했어요 + SQL 적용 안내"를 보인다).
3. Edge Function(`charge-subscriptions`·`register-billing-key`)은 **086a 적용 뒤에** 배포한다(`plan_source` 칸이 없으면 업데이트가 실패한다).
4. `payment-webhook`은 포트원 콘솔에서 웹훅 URL·시크릿을 설정한 뒤 배포(아래 환경 변수).

**되돌리기**: 모두 "추가"라서 새 함수·뷰·표를 drop 하면 이전으로 돌아간다.
- 동작이 바뀐 것: `admin_delete_academy`(운영 학원은 즉시 삭제 → 14일 유예 요청), `admin_set_academy_plan`(남겨 둠 — 사유 없음으로 기록되는 호환용), `admin_academy_search`(083a 시그니처 삭제).
- 이전 동작으로 되돌려야 하면 `supabase/083a`·기존 `admin_delete_academy` 정의 파일을 다시 실행한다.
- 일부 컬럼(`plan_source`·`is_test`·문의 칸)은 남아 있어도 이전 화면에 영향이 없다.

## 8. 자동화별 켜기 조건

모든 생애주기 작업은 **꺼짐 + 모의 실행**이 기본이다. 켜는 순서: ① 시스템 상태 > 자동 작업에서 "대상 미리보기" → ② "모의 실행"으로 대기열 확인(발송 없음) → ③ 메일 발송 키를 서버에 등록하고 발송 함수를 배포한 뒤(**아직 없음**) → ④ 설정에서 "실제 발송"으로 바꾸고 켠다. 같은 (종류, 중복 키)는 한 번만 계획되고, 실패는 최대 3회 백오프 재시도, 언제든 "대기 중 발송 중지"로 멈출 수 있다. 테스트 학원·삭제 대기 학원·원장 이메일이 없는 학원은 대상에서 빠진다.

## 9. 아직 하지 못한 것 / 확인하지 못한 것 / 막힌 것

- **미검증(운영 환경)**: 실제 Supabase에서의 SQL 실행·권한·성능, 실제 포트원 웹훅 수신, 운영 데이터에서의 지표 값. (임시 Postgres에서만 확인)
- **미구현**: 생애주기 메일 발송 함수, 비용 감시 숫자, 공지 초안 상태, 영상 화면 검색·필터, 문의 상세의 FAQ 승격 버튼 위치 재배치(기존 동작은 유지), 앱 버전별 오류 집계, 환불 기록(웹훅 환불 이벤트는 기록되지만 환불액 집계는 없음).
- **막힘/외부**: 메일 발송 키·도메인, 포트원 웹훅 등록, pg_cron 등록, 한 사람이 여러 학원에 속하는 구조(스키마 변경 필요).
- **알려진 한계**: 문제 큐 동기화는 관리자가 "오늘 할 일"을 열 때 실행된다(없을 때 아무 일도 안 일어난다는 뜻은 아님 — 화면이 열릴 때 최신 상태로 맞춘다). 상시 알림이 필요하면 pg_cron으로 `admin_issues_sync`를 호출하는 별도 작업이 필요하다.

## 10. 운영 투입 전 마지막 점검 순서

1. 086a~u 적용 → `086_check.sql` 18줄 true 확인
2. 관리자 계정으로 로그인해 `/admin` 6개 화면에 "불러오지 못했어요"가 없는지 확인
3. "근거 미분류"로 보이는 기존 유료 학원을 확인해 구독/부여로 분류(학원 상세 > 요금제)
4. 테스트로 만든 학원이 있으면 테스트 표시
5. 앱 배포 → Edge Function(결제 2개) 배포 → 웹훅 설정
6. 문의 응답 기한(설정)을 운영 방식에 맞게 조정
7. 생애주기 작업은 계속 모의 실행으로 두고 대상 수만 며칠 관찰
