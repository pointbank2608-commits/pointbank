# 단계별 게임 만들기 구현 (2026-10-20)

## 단어장·문장 모음·우리 반 불러오기 보완

첫 네 가지 선택 카드는 유지한다. 선택 후 입력 단계 상단에 종류별 `내 단어장 불러오기`, `내 문장 모음 불러오기`, `우리 반에서 불러오기`와 `직접 입력`을 제공한다. 홈의 게임 만들기와 개별 게임 안내가 같은 `GameSourcePicker.tsx`를 사용한다.

- 단어/문장 자료는 종류와 현재 학원 범위에 맞는 실제 저장 자료만 표시하고 이름·항목 수를 보여 준다. 불러온 내용은 임시 편집기로 전달한다. 그룹·그림 편집에서도 기존 뜻과 그림·분류를 보존한다.
- 반은 현재 학원의 반 목록에서 고른다. 학생은 기존의 활성 학생 조회 API를 사용하고 현재 반/학원에 맞는 행만 가져온다. 오늘 참여할 학생을 체크하여 가져오며, 원본 반·학생·활동의 저장 반을 수정하지 않는다. 가져올 학생이 없으면 적용을 막고 직접 입력을 유지한다.
- 학습 내용 단계와 별개로 참여 방법 단계에도 반 불러오기를 제공한다. 임시로 지정한 참여자는 원래 게임의 반 명단보다 우선하지만 원본을 갱신하지 않는다. 팀 구분은 기존 팀/차례 패널을 유지한다.
- 로딩·빈 자료/반·빈 명단·실패/재시도 상태를 제공한다. 빠르게 반을 바꾸거나 계정/학원/자료 종류를 바꿀 때 이전 비동기 결과를 적용하지 않는다.
- `check-guide-sources.mjs` Chrome 검증 통과: 자료 종류 필터, 원본 불변, 체크한 학생만 불러와 게임 실행, 다른 학원의 학생 제외, 빠른 반 전환, 빈 반/반 없는 계정, 자료/명단 실패와 재시도, 홈에서 게임으로 명단 전달, 학습 자료와 별도 참가자 사용, 모바일.
- `check-guide-flow.mjs`의 후속 시나리오와 `check-guide-logic.mjs`를 재실행했다. 직접 입력·저장/다시 열기·활동지·수업 연결·입력 복구·자료 구조/뜻 보존 검증 통과. 이번 보완에서 샘플 53종 브라우저 루프는 반복하지 않았으며 53종 설정 검사는 실행했다.
- 빌드(TypeScript + Vite), 린트, diff 공백 검사를 통과했다. 기존 큰 chunk/린트 경고가 남는다. 캡처는 `output/game-source-class-mobile.png`다.

이번 불러오기 보완은 로컬 구현이며 커밋·푸시·배포·운영 SQL은 실행하지 않았다. 이전 단계 안내 릴리스와 구별한다.

## 적용 범위

합의한 53종(게임 번호 1~53)에 단계 안내를 추가했다. 이 작업 중 다른 작업에서 54~60번 게임이 추가되어 관련 파일이 함께 수정 중이었다. 그 작업을 되돌리지 않았으며, 새 게임 종류는 기존 편집기로 연결되는 기본 안내 경로를 제공한다. 새 7종에 53종과 같은 전용 입력 양식을 새로 설계하거나 전수 검증한 것은 아니다.

홈과 게임 목록의 `+ 게임 만들기` → 샘플 / 단어 / 문장 / 학생·팀 이름 → 입력 또는 내 자료 → 가능한 게임 선택 → 게임별 필요한 입력 → 참여 방법(필요한 경우) → 준비 확인 → 실행으로 연결한다. 개별 게임 첫 임시 준비에서도 같은 안내를 열고 이미 고른 게임은 다시 묻지 않는다. 기존 저장 게임과 수업 발표 경로는 유지한다.

## 동작

- 샘플은 각 게임의 실제 설정으로 준비하고 시작한다. 다이어그램과 수박 문장의 체험 자료도 제공한다. 실행만으로 단어장·수업·저장 게임을 생성하지 않는다. 탭 임시 자료는 기존의 계정/학원/게임별 보존 구조를 사용한다.
- 목록·문장·짝·퀴즈·참거짓·그룹·그림 정답은 안내 안의 행별 입력과 붙여넣기를 사용한다. 불러온 그림·분류를 재사용하며 부족한 그림이나 분류를 보완할 수 있다.
- 문장 다리는 선택한 구간을 빈칸과 정답으로 연결한다. 문장 탑은 앞 문장의 경계를 눌러 삽입 위치를 선택하고 결과를 확인한다. 수박 문장은 틀과 문장 자리를, 다이어그램은 그림과 핀 위치·이름을 지정한다. 그림 위치는 키보드로 가운데 핀을 추가할 수도 있다.
- 내장 역할극·수학·타이머는 기본 설정으로 준비한다. 바꾸고 싶은 경우에만 상세 편집기를 펼친다. 기존 게임판/편집기를 복제하지 않는다.
- 이름을 뽑을 재료로 사용하는 것과 학습 활동의 참가자는 구별한다. 필요한 게임에서만 참가자/팀 단계를 제공한다. 수동 차례의 임시 이름, 지원되는 게임의 팀 수, Save it or Give it의 별도 개인 명단, 타이머의 참가자, 번개 피하기의 인원 수를 원래 설정으로 연결한다.
- 저장한 게임을 안내에서 준비하면 원본을 편집하지 않고 임시 사본을 만든다. 게임판의 기존 로컬 상태가 갱신되도록 임시 선택 ID를 새 revision으로 변경한다. 저장 데이터는 기존 명시적 저장 버튼에서만 생성한다.
- 작성 중인 표·붙여넣기·문장 설정은 계정/학원별 session storage에 복구한다. 로그인 정보가 다른 이동 payload는 적용하지 않는다. 실제 원본 자료와 임시 입력을 구별한다.
- 짝 개수·중복, 문제의 보기/정답, 명시적 O/X, 그룹 수, 그림·정답, 문장 빈칸·확장 정합성, 그림 좌표, 문장 자리, 퍼즐 단어 길이를 검사한다. 문제 전용 구조를 임의의 단어 목록으로 해석하지 않는다.
- 문장 잡기·번개 피하기의 단어 지원과 참거짓·대회의 자료 선택 표시를 실제 변환 지원에 맞췄다. 게임 규칙·점수 엔진은 변경하지 않았다.
- 새 문구는 기존 i18n에 한국어/영어로 연결했다. 네이티브 dialog, 단계 제목 포커스, 입력 라벨, 키보드 포커스, 로딩·실패·빈 자료 상태를 제공한다.

## 검증

- `npm run build`: TypeScript + Vite production build 통과. 기존 큰 chunk 경고가 있다.
- `npm run lint`: 오류 없이 완료. 기존 hook dependency/Fast Refresh 및 다른 작업 파일의 경고가 있다.
- `node scripts/games/check-guide-flow.mjs`: 실제 AppLayout·라우트·게임을 합성 계정/API로 Chrome에서 실행. 53종 샘플 준비→실행, 무저장, 직접 이름 입력, 매치업 부족한 짝 안내, 문장 생성 메뉴→호환 게임 전달, 저장 단어장 그룹 재사용, 독립 참가자, O/X 명시 선택, 빈칸 생성, 문장 확장/자리, 상세 편집기, 저장 원본 불변, 새로고침 입력 복구, 모바일 만들기/입력 화면을 검증했다.
- 같은 스크립트의 추가 시나리오로 안내에서 준비한 활동의 명시적 저장/다시 열기, 동일 자료 2개 활동지 전달, 선택 전에 수업 미생성 및 명시적 수업 추가를 검증했다. `GUIDE_SKIP_SAMPLES=1`은 이미 확인한 53종 샘플 루프를 생략하고 후속 시나리오를 실행하는 옵션이다.
- `node scripts/games/check-guide-logic.mjs`: 53종 family/샘플 완전성, 원본 불변, 최소 짝/중복 정답, 퍼즐 경계, 이름·학습자료 분리, 그림/분류 재사용, 문장 다리/탑, 그림 좌표/문장 자리 검증.
- `node scripts/games/check-quick-integrity.mjs`: 실제 공통 API의 임시 수정 DB 미접근, 계정/학원 격리, 로그아웃 차단, 원본 보존, 저장·기존 수업 변환·동시 편집 검증 통과.
- `node scripts/games/check-workspace-logic.mjs`: 기존 자료 변환과 게임 시계 정지/복귀 검증 통과.
- `git diff --check`: 내용 공백 오류 없음. 일부 기존 파일의 LF/CRLF 안내만 있다.
- 모바일 캡처: `output/game-create-mobile.png`, `output/game-guide-mobile.png`를 확인했다. 합성 테스트는 외부 폰트를 차단하므로 앱 바깥쪽 아이콘 일부는 실제 서비스와 다르게 표시될 수 있다.

이번 검증은 실제 운영 계정/RLS/결제 플랜 전체 조합, 실제 다기기 휴대폰 대회, Safari/전자칠판 장비 검증을 대체하지 않는다. 53종 모두의 전체 라운드/점수 계산을 전수 완주한 것은 아니다.

## 유지한 제약

- 실제 휴대폰 대회는 저장한 활동에서 여는 기존 서버 경로를 유지한다. 임시 활동에서는 칠판 체험이며 화면에 차이를 안내한다.
- 팀명 표시 방식은 각 게임의 기존 규칙을 유지한다. 수동 차례 패널에서 이름을 바꿀 수 있으나, 원래 두 팀으로 고정된 게임판의 점수판 이름까지 일괄 변경한 것은 아니다.
- 게임 규칙상 단어장만으로 빈칸·오답·분류·그림 위치를 알 수 없는 경우 교사가 지정한다. 자동 정답을 만든 것처럼 표시하지 않는다.
- 워드서치 길이 검사는 실제 제외 원인 하나를 차단한다. 무작위 퍼즐에 모든 단어가 반드시 배치된다고 보장하지 않으므로 실제 게임판 배치를 확인하도록 안내한다.

## 파일과 확인 방법

주요 파일: `GameCreateButton.tsx`, `GameSetupGuide.tsx`, `gameGuide.ts`, `guideLocales.ts`, `GameWorkspace.tsx`, `GameWorkspaceContext.tsx`, `useGameTemplates.ts`, `gamePreparation.ts`, `DashboardPage.tsx`, `GamesPage.tsx`.

저장소 루트에서 `npm --prefix app run dev -- --host 127.0.0.1` → 로그인 → `/dashboard` 또는 `/games` → `+ 게임 만들기`. 개별 `/games/matchup` 등에서도 안내를 확인할 수 있다. 회귀 스크립트는 app 폴더에서 실행하며 로컬 Chrome과 기존 설치된 Playwright/Vite 도구를 사용한다. 운영 DB에 테스트 자료를 생성하지 않는다.

구현 검증 단계에서는 커밋·푸시·운영 배포·SQL 실행을 하지 않았다. 후속 사용자 요청에 따라 54~60번 새 게임을 제외한 단계 안내 변경만 선별하여 커밋·푸시·Vercel 배포한다. 운영 SQL은 실행하지 않으며, 제외한 게임의 로컬 작업 파일은 보존한다.


## 사다리 결과 입력 개선 (2026-10-21)

- 기존에는 참가자와 결과 개수가 다르면 ‘다음’에서 일반 오류만 상단에 표시해, 긴 입력 화면 아래에서는 반응이 없는 것처럼 보였다.
- 입력한 참가자 수만큼 개별 결과 칸을 표시한다. 부족한 결과 수를 실시간으로 안내하고 ‘다음’에서 첫 빈 결과로 포커스를 옮긴다. 개별 ‘꽝’ 체크와 ‘빈 결과를 모두 꽝으로 채우기’를 제공하며 체크를 해제하면 이전 입력이 복원된다.
- 입력 순서/무작위 배치를 선택하고 기존 config JSON에 `ladderResultOrder`를 선택 속성으로 보존한다. 필드가 없는 기존 활동은 입력 순서를 유지한다. 무작위 배치는 새 사다리를 시작할 때 섞고 라운드 중 리렌더·화면 크기 변경으로 바뀌지 않는다. 입력 원본 배열과 사다리 경로 생성 규칙은 유지한다.
- 이전 여러 줄 결과도 같은 계정·학원의 탭 임시 보존 값에서 읽는다. 참가자를 추가하면 빈 칸이 생기며, 끝 항목을 삭제했다 다시 추가하면 임시 결과를 복구한다. 명시적 활동 저장은 기존 저장 경로를 이용하며 DB 스키마 변경은 없다.
- 샘플은 참가자 6명, 상품 2개와 꽝 4개로 개수를 맞췄다. 공통 준비 검증에서도 결과 수와 빈 라벨을 검사한다.
- `check-ladder-guide.mjs`: 합성 API/계정과 실제 게임 화면으로 6명·결과 2개 재현, 오류/포커스, 꽝 처리/해제, 다음→시작, 모바일·새로고침 복구, 개수 변경, 무작위 배치와 실제 당첨 결과 일치, 원본 순서 보존, 무저장 및 명시 저장/다시 열기를 검증한다. 운영 DB나 실제 사용자 계정 검증은 아니다.
- 로컬 확인: `npm --prefix app run dev` → 로그인 → `/games/ladder` → 학생·팀 이름으로 만들기 → 참가자·결과 입력 → 다음. 회귀 검사는 app에서 `node scripts/games/check-ladder-guide.mjs`로 실행한다.

검증 결과: `npm run build`(타입 검사 포함), `npm run lint`(기존 경고만), `check-guide-logic.mjs`(53종), `check-ladder-guide.mjs`, `git diff --check` 통과. `output/ladder-results-mobile.png`도 확인했다. 커밋·푸시·운영 배포는 이번 수정에서 실행하지 않았다.
