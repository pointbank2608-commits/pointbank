# 그림 속 이름 맞히기 — 기존 그림 연결 (2026-10-28)

화면의 ‘이 게임에 사용할 이미지가 있는 자료가 필요합니다’는 그림 파일을 검사한 결과가 아니었다. `prepareClassroomGame('labeleddiagram', list)`는 배경과 이름표 위치를 단어장에서 자동 생성하지 않으므로 항상 변환 불가였는데, 준비 화면이 이를 이미지 부족으로 표시하며 모든 단어장을 비활성화했다. 기존 GameImagePicker도 업로드만 제공해 사전 그림을 선택할 수 없었다.

## 수정

- 준비 화면에서 그림 속 이름 맞히기의 단어장 불러오기를 허용한다. 단어장은 이름 목록으로 가져온다. 저장 자료 자체는 변경하지 않는다.
- 가져온 단어장은 기존 `enrichCards`로 연결된 사전 그림을 보충한다.
- 준비와 상세 편집 양쪽의 이미지 선택기에 ‘기존 그림에서 고르기’를 연결했다. 가져온 자료의 그림과 그림 사전을 영어/뜻으로 검색하며, 검색 후 URL 중복을 제거하고 24개씩 표시한다. 실제 조회 실패는 빈 검색 결과와 구분하고 재시도할 수 있다.
- 그림 한 장을 배경으로 고르고 각 이름표 위치를 직접 클릭한다. 단어장 그림들을 합치거나 정답 위치를 추측하지 않는다. 이름을 불러온 뒤 아직 위치를 지정하지 않은 항목은 완료 시 구체적으로 안내한다. 좌표가 비어 있는데 Number('')로 0이 돼 완료되는 것도 막았다.
- 직접 클릭해 새 이름표를 만드는 기능과 파일 업로드는 유지했다. 다른 즉시 변환 메뉴에서의 안내도 이미지 부족 대신 그림/위치 준비가 필요하다고 설명한다.
- 자동 저장, 새로운 게임 모드, 채점 로직, DB 구조 변경은 없다. 후속 사용자 요청으로 이번 변경만 선별 커밋·푸시하고 운영 배포를 진행한다.

## 확인

`app/scripts/games/check-diagram-images.mjs`: 실제 Chrome + UX점검 합성 API로 단어장 활성화, 이름 가져오기, 사전 그림 검색/실제 이미지 로딩, 빠진 위치 오류, 위치 지정 후 완료→시작 전, 명시 저장의 배경·이름·좌표 보존, 중앙 시작을 확인했다. 완료 전 서버 쓰기 0회, 브라우저 예외 없음. 결과: `output/ux-remaining/diagram-image-results.json`.

관련 파일 oxlint 통과. TypeScript를 포함한 `npm run build` 통과(기존 번들 크기 경고). 결과: `output/ux-remaining/diagram-image-build.txt`.

운영 계정의 화면에 나온 각 단어장 내용이나 사전 이미지 전체의 유효성은 전수 검사하지 않았다. 그림이 사전/단어장에 연결돼 있어야 검색되며, 파일이 존재하는 것만으로 뜻·정답 위치를 자동 추정하지 않는다. 운영 데이터는 변경하지 않았다.
