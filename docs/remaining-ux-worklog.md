## 이미 해결돼 유지한 부분

- 수업에 추가의 실제 저장 API와 스냅샷 생성, 동시 수정 시 append 보호 방식은 유지했다. 성공 안내는 원래처럼 저장 완료 후에만 나온다.
- 2단계 준비, 지원하지 않는 방식의 회색 비활성/이유, 개별 입력과 붙여넣기, 단어·문장 불러오기, 학생 이름 콘텐츠와 점수/참여자 설정의 구분을 유지했다.
- 저장하지 않고 준비·실행하는 기능, 반별/공용 범위와 RLS, 수업 연결을 유지했다.
- 문법 탐정의 정답 제안/수동 범위/추가 정답, 다른 게임의 정답·오답·재도전 로직을 변경하지 않았다.
- 파닉스 그림·음성 소스와 워크북은 수정하지 않았다. 단어에 연결되는 기존 그림과 발화 문자열을 검증했다.

## 실제 브라우저 범위와 한계

- Chrome headless에서 실제 React 페이지·편집기·게임·라우터를 실행했다. 인증/API는 UX점검 합성 backend로 대체했고, 저장/추가/실패는 이 backend와 sessionStorage에만 기록했다. 새로고침 유지도 이 격리 환경에서 검증했다. **운영 DB 저장·RLS 검증 결과로 해석하면 안 된다.**
- 실제 운영 URL도 Chrome에서 확인해 풍선/낚시/기차의 완료 의존성과 문법 탐정 문장 비활성을 재현했다. 이때도 Supabase 응답은 격리했다. 수정본은 배포하지 않았으므로 운영 수정 완료를 주장하지 않는다. `output/ux-remaining/production-baseline.json`.
- 실제 사용자의 Voca King 수업은 열거나 변경하지 않았다. 일치하는 기존 저장 형식의 합성 수업으로 원인을 재현·검증했다.
- 파닉스 음성은 브라우저의 발화 요청 문자열 연결을 검사했다. 스피커 실청·음질·실제 전자칠판·iOS Safari는 확인하지 않았다. 공 돌리기 음악도 실제 청취 대신 재생 호출/인스턴스/DOM 및 공통 시계 검사를 사용했다.
- 모든 게임의 모든 설정 조합과 실제 운영 권한 조합까지 브라우저로 전수 검사하지는 않았다. 공통 구조 검사와 주요 실제 흐름 검사를 구분해 위에 적었다.
- 기존 수업 추가는 게임 스냅샷 생성과 수업 append가 별도 요청이다. 두 번째 요청이 실패하면 연결되지 않은 스냅샷이 남을 가능성은 기존처럼 남는다. 성공처럼 안내하지 않으며 대상/입력을 보존해 재시도할 수 있다. 임의 정리/삭제나 DB 트랜잭션 변경은 하지 않았다.
- 반복 검증 중 발견한 완료 상태 전달 경합은 최종 코드에서 보강했고 전체 흐름이 통과했다. 최종 성공 JSON과 과거 실패 진단 PNG는 구분해야 한다.

## 배포 전 재검증

게임 UX·수업·파닉스 보완 검사 3종을 다시 실행해 모두 통과했다. 운영에 반영할 UX 파일만 HEAD 위에 복사한 별도 스냅샷에서 TypeScript/Vite 빌드를 확인한다. 다른 작업의 스테이징된 문법 워크북 삭제와 라우트·메뉴 교체는 이번 커밋에 포함하지 않는다.
