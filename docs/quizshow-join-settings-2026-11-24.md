# 휴대폰 참여 보카 대회 입장·설정

- 임시 활동을 강제로 `preview`/`autoPreview`로 실행하던 경로를 제거했다. 정상 실행은 **대회 열기(QR 만들기)**를 눌러 기존 `live_host_create`를 호출하고 QR·6자리 번호가 있는 대기실로 진입한다. 임시 활동은 `templateId: null`, 저장한 활동은 해당 ID를 사용한다. 학생 `/join`, `/join/:code`는 그대로다.
- 학생 휴대폰 모형과 로컬 모형 응답 생성 코드를 삭제했다. 명시적으로 선택한 미리보기와 활동 추가의 수업 미리보기는 칠판만 보여주며 대회 생성·참가·응답 기록을 만들지 않는다.
- 이 게임의 공통 상단 **반 설정**은 비활성화한다. 다른 게임의 반 설정은 유지한다. 참여자는 실제 휴대폰 입장으로 정한다.
- 공통 게임설정의 라운드는 이름·체크박자·펼치기/접기로 표시한다. 기본 접힘이며 문제 수·제한 시간·점수·순서를 펼쳐 수정한다. 접기/순서 이동은 값과 선택을 지우지 않는다.
- 예상시간은 편집 중인 자료를 기존 `gameEditContent`로 변환한 실제 출제 가능 문제를 기준으로 계산한다. 질문별 제한 시간 + 확인 10초, 라운드별 전환 10초. 카운트다운이 없는 부저는 답변·판정 30초 + 확인 10초로 잡는다. 전체/퀴즈별 분 단위 올림으로 표시하며 학생 입장 시간은 제외하고 실제 진행에 따라 달라짐을 안내한다. 사용자 지정 문항은 기존 편집 변환 규칙을 유지한다.
- 실제 대회의 학생 답·참가자·서버 채점·학습 센서는 변경하지 않는다. 추가 DB 마이그레이션은 없다.

검증: `npm run build`, `node app/scripts/games/check-quizshow-join.mjs`(실행 cwd는 app이면 scripts부터), `HISTORY_TYPES=quizshow node app/scripts/games/check-game-history-matrix.mjs`. 브라우저 테스트는 로컬 격리 서버이며 학습 센서를 명시적으로 끈다. 실제 운영 검증은 QR 대기실·학생 입장 폼까지만 확인하고 합성 학생 응답을 제출하지 않는다.
