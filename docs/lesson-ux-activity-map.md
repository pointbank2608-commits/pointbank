## 확인된 단어장 원인

`CurriculumPage`가 바깥 선택 반에 한정해 조회한 목록을 `QuickLessonWizard`에 전달했고, 팝업은 자체 반 선택을 바꿔도 재조회하지 않았다. 따라서 다른 반 단어장을 찾을 수 없었다. 바깥 reload에도 응답 순서 보호가 없었다. 실제 단어장 페이지와 같은 `fetchWordLists(academy, class)`(선택 반+공용, 기본 word 종류)을 팝업의 현재 반으로 조회하고 늦은 응답을 폐기한다. 로딩·오류·빈 목록을 구분하고 재시도한다.

기준 커밋 `4021190d`의 기존 컴포넌트를 별도 로컬 서버에 로드해, 바깥 A 반에서 팝업만 C 반으로 바꾸었을 때 C 단어장이 보이지 않는 현상을 재현했다. 동일 합성 데이터에서 수정본은 C 단어장과 공용 자료를 정상 조회했다. 운영 DB의 특정 반 데이터를 추정한 결과가 아니다.

## 구현·저장 보호

- 반 탭을 생성 버튼 위로 이동하고 영역을 ‘새 수업 만들기’와 ‘내 수업’으로 구분했다.
- 직접 만들기의 추천 접기 기본값만 바꿨다. 영상·샘플에서 자동 진입하는 기존 경로는 유지했다.
- 작성 시작 시 반을 보관해 목록 재조회와 저장 대상이 엇갈리지 않게 했다. 공용 수업의 null 반도 유지한다. 작성 중 다른 반을 선택하면 기존 변경 확인 절차를 거친다.
- 단어·게임·활동지 카탈로그와 기존 추가/교체 함수를 사용한다. 단어·활동·템플릿 데이터 구조, 게임 엔진, 영상 재생 방식, SQL, 권한 정책은 변경하지 않았다.
- 실제 추가를 완료한 항목만 사용자·학원별 기기 최근 목록에 저장한다. 기록이 없으면 ‘기본 활동’으로 표시한다.
- 묶음은 기존 활동 뒤에 4개를 추가하며 종류 바꾸기에서는 기존 교체 규칙과 helpers를 보존한다. 묶음의 게임 내용을 만들 수 없으면 부분 완료로 표시하지 않는다.
- 카드 버튼은 수업 시작을 한 줄 전체로, 수정·숙제 내기·더보기를 다음 줄로 정렬한다. 숙제가 비활성화된 계정의 기존 기능 제한도 유지한다.

## 검증 결과

- 신규 브라우저 12개 검증 묶음 통과. 기존 단체수업 블록 103개를 전부 순회하여 분류 누락이 없는지 비교했다. 전체 대응 데이터는 `output/lesson-ux/activity-map.json`에 있다.
- 반별·공용 조회, 빠른 반 전환과 역순 응답, 로딩/실패/실제 빈 목록, 재시도, 팝업 재진입, 새로고침을 확인했다.
- 추천으로 만든 수업과 직접 만든 수업의 저장 반을 실제 mock 저장 결과와 비교했다. 고른 단어장 ID·단어가 게임 구성까지 이어짐을 확인했다.
- 직접 구성의 추천 접기/펼치기, 전역 검색과 별칭, 기록 없는 기본 활동, 완료한 활동의 최근 기록, Escape/포커스 복귀를 확인했다.
- 미디어·입력 부족 게임·읽기 입력 취소 시 빈 활동이 생기지 않았다. 빈칸 듣기와 두 무지개 문법의 초기 모드가 구분된다.
- 묶음 더블 클릭 시 기존 STEM 활동을 유지하면서 4개만 추가됐다. 기존 수업 수정·저장·새로고침 후 수업 ID·기존 활동 ID·순서가 유지됐다. 보조 타이머는 활동 수를 늘리지 않았다.
- 수업 시작은 기존 시작 전 점검으로 연결되고, 더보기 항목 5개와 숙제에 전달하는 수업/반 ID를 확인했다.
- 1440px PC, 1024px/768px 태블릿, 390px 모바일과 844×390 가로 화면을 확인했다. 팝업 배경 스크롤 잠금, 고정 검색/카테고리, 오른쪽 목록 스크롤, 버튼 글자 넘침을 확인했다.
- 기존 숙제 브라우저 회귀 11개 통과. 타입 검사·프로덕션 빌드와 변경 코드 lint 통과. 빌드의 기존 대형 청크 경고는 남아 있다.

검증은 별도 합성 반·수업·단어장·저장 API를 사용했다. 운영 수업·단어장·학생 기록을 수정하지 않았다. 실제 Supabase 계정별 권한, 실제 파일 업로드, 실제 교실에서의 수업 실행·기기별 전체화면은 이번 격리 검사로 검증했다고 주장하지 않는다. 해당 로직과 정책은 변경하지 않았다.
