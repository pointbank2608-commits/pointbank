# 학부모 페이지 `/p`

선생님은 **학생 등록** 또는 학생 이름 옆 **학생 정보 수정**에서 보호자의 동의를 확인하고 학부모 성함·전화번호를 입력한다. 칭찬 통장의 학생 등록에서도 같은 화면을 사용한다. 학생과 계정 정보는 서버에서 함께 저장하며 중간 실패는 롤백하고 같은 요청의 재전송은 기존 학생을 반환한다. 학부모는 `/p`에서 등록된 성함·전화번호로 로그인하고, 같은 정보가 등록된 형제자매를 함께 확인한다. 이름의 공백과 전화번호의 하이픈은 비교할 때 정리한다. 학생 `/s`에서는 학생 이름을, 학부모 `/p`에서는 학부모 성함을 입력한다. 전화번호는 암호화해 보관하고 로그인 검색에는 비밀키를 사용하는 HMAC을 쓴다. 잘못된 로그인은 이름별 10분 8회 뒤 차단한다.

기기 연결은 최대 180일이다. 보호자 성함이나 전화번호를 변경하거나 계정을 삭제하면 해당 학생의 기존 기기와 대기 링크가 해제된다. 예전에 전달한 1회용 링크도 유효기간 안에서는 사용할 수 있다. 한 학생당 등록 보호자는 현재 한 명이며 푸시를 켜면 로그인된 형제자매 전체에 적용한다. 학생관리의 학부모 계정·피드백 패널에서는 등록 상태 확인과 피드백 발송을 하고, 정보 변경은 학생 정보 수정 화면으로 이동한다. 성함·전화번호 입력은 기존 학생 로그인과 같은 인증 수준이며 휴대폰 소유 확인용 인증문자는 제공하지 않는다.

학생은 `/s`에서 이름과 등록된 학생 또는 보호자 번호로 들어간다. 선생님이 미등록 학생의 첫 로그인 번호를 등록할 수 있고, 기존 번호 변경·조회·삭제는 원장이 관리한다.

안드로이드는 Chrome에서 `/p`를 열고 로그인 후 **푸시 켜기**를 누른다. iOS/iPadOS 16.4 이상은 Safari에서 **홈 화면에 추가**를 먼저 하고, 홈 화면 앱에서 같은 성함과 전화번호로 로그인해 알림을 허용한다.

| 종류 | 발행 기준 | 완료 기준 |
|---|---|---|
| 온라인 숙제 | 개인 배정 대상이 생성됨 | 서버 제출 완료 |
| 개별 숙제 | 개별수업을 숙제로 배정 | 서버 전체 완료 |
| 문법 숙제 | 문법 숙제로 배정 | 서버 최종 완료. 필요한 복습이 남으면 별도 표시 |
| 단어암기 프로젝트 | 개인 배정 대상이 생성됨 | 전체 완료 표시 없음. 하루 분량 완료를 전체 완료로 처리하지 않음 |

| 제공 소식 | 연결하는 서버 기록 | 페이지와 푸시 동작 |
|---|---|---|
| 발행·이행 | 온라인 숙제 대상·제출, 개별 숙제·문법 숙제 최종 완료 | 배정이나 완료 시 알림 생성 |
| 마감 후 미완료 | 마감일이 지나도 완료 기록이 없는 활성 숙제 | 기존 1분 발송 작업에서 확인해 한 번 알림. 완료되거나 닫히면 대기 중 미완료 알림 제외 |
| 단어 학습 | `wm_sessions.done_at`와 당일 학습 기록 | 오늘 분량 진행·완료를 표시하고 하루 분량 완료 알림 |
| 교사 숙제 확인 | 기존 칭찬 통장의 `transactions.is_homework` 기록 | 숙제 완료 지급·미제출 차감과 같은 검사 기록을 알림. 일반 포인트는 제외 |
| 출석·하원 | 기존 출석부 `attendance` | 선생님이 저장한 출석·하원·수정·삭제 알림. 기록 없는 날의 결석은 추정하지 않음 |
| 학생 피드백 | 선생님이 확인하고 보내는 `parent_feedback` | 학부모 알림함에 본문 표시, 수신을 켠 기기에 피드백 도착 알림 |

선생님의 학생 대상 채팅, 내부 분석값이나 초안은 학부모에게 자동 공개하지 않는다. 기존 **학습 카드 → 학부모 리포트**에서 자동으로 구성된 기록과 선생님 한마디를 확인·수정하고 **학부모에게 보내기**로 바로 발행할 수 있다. 학생관리의 피드백 작성란에서도 메시지를 보낼 수 있다. 학생의 수행은 기존 서버 채점·완료 처리에서 자동 연결하므로 학생에게 별도 제출 버튼을 요구하지 않는다.

알림함은 기존 숙제 이력과 새 출석·피드백 소식을 통합한다. 푸시는 수신을 켠 뒤 새로 발생한 사건을 대상으로 하며 잠금 화면에는 소식 종류만 표시한다. 출석부 날짜 표시(`day`)나 옛 기록(`unknown`)에 들어 있는 시각을 실제 등원 시각으로 보여주지 않는다. 새 등원 버튼 기록(`time`)만 시각을 표시한다. 오프라인 숙제는 통장의 교사 검사 기록을 전달하며 온라인 마감 시각으로 미완료를 추정하지 않는다. 온라인 수행 완료와 교사의 통장 확인은 서로 다른 소식으로 표시한다. 완료 기록은 수행 사실이며 학습 성과 판정은 후속 평가가 필요하다.

## 반별 소통과 비공개 문의

교사용 출석부에서 반을 고른 뒤 **이 반의 학부모 소통 설정·문의**를 연다. 숙제 발행·시작·완료·미완료, 출석, 피드백, 문의를 각각 설정한다. 기존 반의 시작·문의는 기본 꺼짐이다. 숙제 시작은 온라인 시도 생성, 개별 숙제 시작 시각, 문법 실행 연결, 단어 프로젝트 첫 일일 세션을 기준으로 배정당 한 번 기록한다.

교사는 자신을 문의 담당자로 지정할 수 있고 원장은 같은 학원의 선생님을 지정하거나 교체할 수 있다. 담당자는 자기 기기에서 문의 푸시를 켠다. 학부모는 자녀를 선택한 뒤 비공개 문의를 작성한다. 해당 반 담당자가 한 번 답변할 수 있으며, 학부모와 담당 교사용 잠금 화면에는 본문이 표시되지 않는다. 자녀의 반이나 보호자 정보가 바뀌면 현재 연결과 일치하는 문의만 조회한다.

136까지 적용된 환경의 다음 배포 순서는 `137_class_communication.sql`, `parent-push` 함수, 웹앱이다. 기존 푸시 키와 1분 작업을 재사용한다.

## 적용 및 확인

1. 기존 133·134가 적용된 환경에서 확장된 알림 종류를 처리하는 `parent-push` 함수를 먼저 배포한다. 다음으로 `supabase/135_parent_login_updates.sql` → `supabase/135_check.sql` → `supabase/136_student_parent_info.sql` → `supabase/136_check.sql`을 실행하고 마지막으로 앱을 배포한다. 135는 기존 보호자 계정의 로그인 검색키도 자동으로 채운다. 새 앱의 출석 저장 API는 135의 `check_in_kind` 컬럼이, 학생 등록·수정과 형제자매 푸시는 136의 함수가 필요하다.
2. 환경마다 VAPID 키를 한 번 생성한다(예: `npx web-push generate-vapid-keys`). 공개 키는 Edge Function의 `PARENT_PUSH_PUBLIC_KEY`로 저장하고 개인 키는 함수 비밀 `PARENT_PUSH_PRIVATE_KEY`로만 저장한다. `PARENT_PUSH_SUBJECT`에는 운영 연락용 HTTPS 주소 또는 `mailto:` URI를 쓴다. 별도의 32자 이상 무작위 `PARENT_PUSH_CRON_SECRET`을 Edge Function과 Vault(`parent_push_cron_secret`)에 같은 값으로 보관한다.
3. Vault에 `parent_push_project_url`(프로젝트 Supabase 주소)과 `parent_push_gateway_jwt`(같은 프로젝트의 anon JWT)를 저장한다. 기본 JWT 검사를 켠 채 `parent-push` Edge Function을 배포한 뒤 `supabase/133_parent_push_schedule.sql`을 적용한다. 함수는 별도 크론 비밀도 검증한다. 발송 준비를 확인한 뒤 `public.private_config`의 `parent_push_public_key`에 공개 키를 저장하면 학부모 API가 연결된 기기에 그 키를 제공한다. 대기열은 1분마다 처리하며 일시 실패는 최대 5회 시도한다.
4. 실기기에서 Android Chrome 및 iPhone 홈 화면 앱 각각에서 학부모 성함·전화번호로 로그인한다. 푸시를 켠 뒤 숙제 발행·완료·마감 후 미완료, 출석·하원, 교사 피드백 발송을 확인한다. 같은 자녀의 알림함으로 열기, 푸시 끄기, 로그아웃, 교사의 연결 해제도 확인한다.

푸시를 즉시 중지하려면 `select cron.unschedule('parent-push');`를 실행한다. 페이지의 현황과 알림함은 계속 확인할 수 있다. 공개 키를 교체할 때는 이전 브라우저 구독을 다시 등록해야 한다.

로컬 합성 권한·상태·대기열 검사: `node app/scripts/homework/check-parent-portal.mjs`. 모바일 화면과 등록·해제·알림함 검사는 `node app/scripts/homework/check-parent-portal-browser.mjs`(API와 브라우저 구독은 합성). 도구를 다른 경로에 설치했다면 `PARENT_TEST_NODE_MODULES`에 PGlite·Playwright Core가 들어 있는 `node_modules` 경로를, 별도로 설치한 Chrome을 쓸 경우 `PARENT_TEST_CHROME`에 실행 파일 경로를 지정한다. Deno에서는 서버 함수 타입 검사와 합성 푸시 서비스에 대한 VAPID 암호화·HTTP 결과 처리를 확인했다. 운영 반영과 실기기 수신은 별도로 확인한다.
