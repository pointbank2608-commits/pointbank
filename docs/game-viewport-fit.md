# 게임 화면 맞춤

일반 게임의 `GameThemeFrame`과 파닉스 `GameSession`이 `app/src/lib/gameViewportFit.ts`의 `useGameViewportFit`을 사용한다. 일반 실행·브라우저 전체화면·수업 발표에서 같은 계산을 쓴다. 게임의 질문·규칙·점수와 학습 센서 호출은 바꾸지 않는다.

- 상단 도구줄과 차례 표시는 확대 대상 밖에 둔다. 남은 영역 안에서 게임판·글자·오브젝트를 함께 동일한 비율로 확대/축소한다.
- 게임 캔버스는 가용 폭과 1280px 중 작은 폭으로 먼저 배치한다. 실제 그려진 영역을 측정해 가로/세로 중 제한되는 쪽까지 맞춘다. 투명한 전체 폭 래퍼를 게임판 크기로 오인하지 않는다.
- 회전·흔들림이 오브젝트 크기를 바꾸지 않게 기본 레이아웃 크기를 사용한다. 그림·글꼴 로드, 창 크기 변경, 문항/결과 변경, 애니메이션 완료 때 다시 맞춘다.
- 스크롤 가능한 보조 목록은 그 목록의 보이는 영역만 측정한다. 글자가 많다는 이유로 게임 전체를 불필요하게 줄이지 않는다.
- 일반 게임의 기존 공용 배경은 프레임 전체에 `cover`로 표시한다. 자체 장면 배경이 있는 게임은 그 배경을 프레임으로 확장하고 원래 배경 중복 표시를 없앤다. 보드와 캐릭터 자체는 자르거나 비율을 바꾸지 않는다. 화면과 그림의 비율이 다르면 배경 그림의 가장자리는 잘릴 수 있다.
- 파닉스 일반 실행도 게임 전용 화면을 사용한다. 발표 때의 기존 1440px 폭 제한을 없애 배경이 발표 영역 전체를 채운다.
- 캔버스의 DOM 부모를 바꾸거나 게임을 다시 마운트하지 않는다. 전체화면 전환·창 크기 변경 때문에 현재 문제·뽑힌 단어·게임 결과가 초기화되지 않는다.

## 검증

`app/scripts/lessons/check-game-viewport-fit.mjs`는 가짜 API로만 동작하는 로컬 fixture에서 등록된 일반 76개와 파닉스 48개를 각각 실행하고 전체화면·수업 발표로 연다. 1920×1080에서 372가지 구성을 확인한다. 캔버스 가로/세로 배율 동일, 가용 영역 최대 사용, 게임판과 조작 버튼의 화면 경계를 검사한다. 이는 기본 플레이 화면의 배치 검증이며 실시간 학생 접속이나 모든 게임의 모든 결과 상태 전수검사를 뜻하지 않는다.

선택 검증 환경 변수:

- `FIT_TYPES=wheel,twodice,wordtrain,quiz,sound-balloons`: 일부 게임만 검사한다.
- `FIT_VIEWPORT=1366x768`: 화면 크기를 지정한다. 대표 8개 게임을 1366×768·3440×1440·1024×768의 세 모드(72가지)로 확인했다.
- `FIT_INTERACTIONS=1`: 돌림판 결과와 주사위 단어가 전체화면·리사이즈 후 유지되는지, 긴 문장 기차와 긴 질문/보기가 들어가는지 확인한다.
- `GAME_FIT_OUTPUT`: JSON 측정값과 대표 JPG 화면을 저장할 출력 폴더.

반 설정 변경은 `check-shared-class-settings.mjs`, 두 주사위의 기존 기능은 `check-two-dice-class-settings.mjs`로 별도 확인한다. 테스트는 운영 학생·수업 자료나 학습 기록을 사용하지 않는다.
