# 맞춤 단어 숙제 v1 — 2026-11-06

## 사용 흐름

- 선생님: **숙제 → 맞춤 단어 숙제 만들기**. 단어장, 기존 수업의 어휘 자료, 직접 입력 중 하나를 고른다. 목표는 뜻을 보고 영어 단어를 혼자 쓰기다. 짧게 최대 4단어 / 보통 최대 8단어. 큰 단어장은 묶음을 고른다. 나머지 묶음은 자동 배정하지 않는다. 학생 선택·첫 학습 기한·글자 조합/직접 쓰기 연습은 펼쳐서 바꾼다.
- 추천 확인 화면에서 **먼저 확인 → 배우고 연습 → 혼자 확인 → 시간을 두고 확인**과 현재 단어·학생·분량을 보여 준다. 복습 확인까지 명시적으로 승인한 뒤 한 번 배정한다. 승인 전에는 숙제·센서가 생성되지 않는다. 네 단계 순서와 확인 기준은 이 버전의 공통 틀이다.
- 학생: **학생 홈 → 숙제**에서 시작한다. 첫 답이 맞으면 같은 단어의 설명/연습을 줄이고 혼자 확인으로 간다. 어려운 단어만 예시·설명·짧은 연습으로 간다. 혼자 확인이 어려워도 추가 설명/연습은 최대 한 번이다. 첫 학습 완료와 학습 성과는 구분한다.
- 첫 학습을 끝내면 약 1일·7일 뒤의 확인을 같은 승인 계획 안에서 이어간다. 아직 확인일이 오지 않았으면 시작 대신 일정을 보여 준다. 첫 학습 기한은 안내용이며 이후 복습을 끊지 않는다. 복습 간격과 단어 수는 초깃값이다. 최적 효과를 검증한 수치는 아니다.
- 선생님 **맞춤 단어 숙제 진행**에 배정별 첫 완료·복습 응답과 학생 상태가 나온다. 어드민 **학습 연구실 → 맞춤 단어 숙제 분석**은 승인 기간별 계획·배정·학생·첫 완료와 지연 참여/정답·기한/누락·수집/채점 연결을 집계한다. 미응답을 오답으로 넣지 않는다.

## 서버와 센서 계약

- `101_adaptive_homework.sql`은 097~100 뒤에 적용한다. 승인 RPC `learning_homework_assign`이 099의 경로 엔진과 불변 제공 버전/채점을 재사용한다. `learning_homework_plans`에 승인자·시각·원본 종류/ID·분량·첫 기한·규칙 버전을 비공개로 보관한다. 실제 제공 내용은 승인한 카드 및 불변 스냅샷이 기준이다.
- 101은 기존 099 래퍼 여섯 개를 다시 만들지 않는다. 최신 `solo_assignment_for`의 학생/학원 범위 확인 뒤에 맞춤 숙제용 기능 확인을 추가한다. 알려진 형태를 벗어난 함수면 적용을 중단한다. 앞으로 이 도우미를 고칠 때 `learning_homework_guard`를 유지하고 `101_check.sql`과 `099_check.sql`을 확인한다. 보호 호출이 사라지면 새 숙제 배정을 중단한다. 기존 배정의 게이트를 지키려면 교체 직후 검사한다.
- 현재 맞춤 숙제에는 학원의 `homework`와 `solo`가 모두 열려 있어야 한다. 일반 숙제와 일반 개별수업에는 이 추가 결합 조건을 적용하지 않는다. 새 경로는 `kind=homework`로 표시하되 같은 서버 학습 경로를 사용한다.
- 새 실행에 `learning_mode='homework'`와 `learning_rule_version='adaptive-homework-v1'`를 연결한다. 기존 실행의 미상 값은 추정해서 덮지 않는다. 플레이어의 관측과 서버 채점을 기존 run/제공 버전/목표/문항으로 연결한다. 별도 교사·부모 기록은 없다.
- 서버는 다른 학원/반/학생, 잘못된 재료, 한도 초과, 늦은 일정, 같은 요청의 다른 내용, 익명 배정을 차단한다. 배정과 승인 메타데이터는 한 트랜잭션이다. 응답이 유실되면 동일 요청 ID·내용으로 확인한다.
- `101_rollback.sql`은 새 승인 권한만 회수한다. 이미 승인한 학습/복습과 근거를 보존한다. 복구는 `101_adaptive_homework.sql` 재적용 후 `101_check.sql`이다. 운영 클라이언트 수집 중지는 기존 빌드 플래그를 사용한다.

## 범위와 검증

- 첫 버전은 단일 영어 단어의 뜻→철자 회상이다. 문장·영상·말하기·팀 게임은 기존 숙제 경로에서 사용한다. 최근 수업의 개인별 채점 근거를 이용한 진단 생략, 새로운 문맥으로의 전이, 자유 블록 조합, 비교 실험 배정은 후속 범위다. 현재 분기는 해당 숙제의 첫 수행을 쓴다. 관측한 활동을 집중이나 외부 도움으로 간주하지 않는다.
- 격리 DB `node app/scripts/admin/test-adaptive-homework.mjs`: 승인 전·교차 권한·한도·중복·독립 확인·지연 분모·실행 모드·학습 기록 보존 검사 통과.
- 실제 PostgreSQL 16, `test-learning-concurrency.mjs --homework --research --workers=8 --rounds=3`: 동일 승인 8건이 계획/배정 한 건을 만들고, 기존 열기·제출·완료·재시도/어드민 검사도 통과. 서버 종료.
- `node app/scripts/homework/check-adaptive-homework-browser.mjs`: 실제 앱 컴포넌트와 격리 SQL. 단어장 묶음 선택, 승인 전 무배정, 응답 유실 뒤 동일 요청, 글자 조합 정답, 학생 홈/390px 완료와 대기, 어드민 수집 확인. 외부 요청을 차단했다.
- 분리된 Supabase 스테이징: 101 검사 9개, 실제 DB 역할·JWT claim 교사/학생/어드민·기능 차단·센서 흐름, 합성 자료 롤백, 중지/복구 모두 통과. 새 로그인 자격증명이나 서비스 키는 사용하지 않았다.
- 기존 숙제 로직, 포털 브라우저, 099 호환, 연구실 DB, 전체 TypeScript 및 격리 운영 빌드 통과. 빌드 경고는 기존 큰 청크·플러그인 시간 안내다.
- 운영 Supabase에 101 적용 완료. 9개 보호 검사, 기존 배정/채점 수 보존, 운영 테스트 계획 없음 확인. 앱은 이번 main 푸시의 Vercel 자동 배포로 반영한다. 운영 학생을 대상으로 시험 배정을 만들지 않았다.
