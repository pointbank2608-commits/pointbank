# 게임 화면 맞춤 (2026-10-21)

## 변경

- `GameThemeFrame.tsx`: 데스크톱(가로 768px 이상)의 집중 플레이·전체화면·수업 발표에서 실제 무대의 가로와 세로 중 더 제한적인 크기에 맞춰 동일 배율로 조절한다. 무대 패딩과 공통 차례 표시가 차지하는 공간을 제외한다.
- 기존에는 필요한 배율이 0.75 미만이면 갑자기 1배 + 스크롤로 전환했다. 데스크톱에서는 이 전환을 제거했다. 일반 미리보기에도 기존 0.5배 하한 대신 더 작은 배율을 허용한다.
- 좁은 화면에서는 0.75배 미만으로 줄여야 하는 경우 원래 크기와 내부 스크롤을 유지한다. 사다리와 시한폭탄은 기존 모바일 화면 맞춤 정책을 유지한다. 설정·편집 모달의 스크롤은 변경하지 않았다.
- 창 크기·폰트·이미지 로드뿐 아니라 결과 내용의 DOM 변경과 visualViewport resize에도 다시 계산한다. 게임을 remount하거나 진행/점수/시간을 초기화하지 않는다.
- Sentence Splash의 가로폭만 보는 별도 최대 1.9배 CSS zoom을 제거해 공통 프레임이 전체 크기를 관리한다. 색상·그림·벽돌 배치·게임 규칙은 유지한다.

## 로컬 확인

`cd app` 후 `npm run dev`. 로그인 후 원하는 게임에서 샘플 → 게임 시작. 브라우저 크기를 바꾸고 메뉴의 전체화면으로도 확인한다. Sentence Splash는 성공/실패 후에도 다음 문장·다시 도전 버튼과 하단 문장 칸이 보이는지 확인한다.

자동 검증: `node app/scripts/games/check-viewport-fit.mjs` (저장소 루트). 설치된 로컬 Chrome과 기존 Vite/Playwright 테스트 런타임을 사용한다. API와 인증은 합성 데이터이며 운영 DB에는 쓰지 않는다. `FIT_FOCUS=sentencesplash,bomb` 환경변수로 게임을 제한할 수 있다.

## 범위와 한계

공통 프레임을 사용하는 게임 화면의 표시 정책을 변경했다. 게임 규칙·자료 모델·저장/인쇄 기능은 변경하지 않았다. 전체 게임의 모든 승패 조합이나 실제 교실 데이터 최대 크기, Safari/iOS 실기기, 실제 수업 발표 세션은 별도 검증이 필요하다. 항목이 매우 많거나 창 높이가 극단적으로 작으면 데스크톱 글씨가 작아질 수 있다. 모바일은 모든 내용을 억지로 한 화면에 축소하지 않는다. 운영 배포는 진행하지 않았다.

## 검증 결과

- `npm run build` (TypeScript + Vite), `npx tsc -b`, `npm run lint`: 통과. 기존 lint/번들 크기 경고는 남아 있다.
- `check-viewport-fit.mjs`: 실제 카탈로그 60종 모두 1366×768 / 1024×768 / 390×844 샘플 진입, 데스크톱·태블릿 게임 높이 맞춤, 페이지 가로 넘침 없음, 모바일 마지막 버튼 접근 확인. 인증·API만 합성, 실제 게임과 공통 앱 레이아웃을 렌더링한다.
- Sentence Splash: 실제 정답 클릭 → 성공 → 다음 문장 → 시간 초과 → 실패. 결과 버튼·하단 문장 영역 화면 안 표시, 1920×1080 / 1280×600 크기 변경에도 결과 유지, 큰 글씨·영어 표시 확인.
- `TURN_FOCUS=1 node app/scripts/games/check-turns.mjs`: 시한폭탄 차례·연타 방지·타이머·모바일 전체화면·터치·큰 글씨·영어, 틱택토/팝콘/타이머 차례 회귀 검사 통과.
- `check-ladder-guide.mjs`: 결과 입력·순서/무작위·저장/재열기, 넓은/노트북/모바일, 전체 결과 공개 후 한 화면 표시·중앙 정렬 통과.
- `check-splash-spread.mjs`: 390 / 768 / 1440 / 1900px 벽돌 겹침 방지·분산 배치 통과.
- 캡처: `output/game-fit-splash-success.png`, `game-fit-splash-failed.png`, `game-fit-mobile.png`. 데스크톱 성공 화면과 모바일 실패 화면을 실제로 열어 검토했다.
