# 단어암기숙제 (2026-10-26)

선생님이 단어장(또는 초등 800 레벨)을 한 번 고르면, 학생이 여러 날에 걸쳐 짧게 학습한다. 같은 단어를 **간격을 두고, 다른 활동·단서로** 다시 만나 "알아보기 → 스스로 떠올리기"로 이어지게 한다. 문제·정답·일정은 서버가 만들고 학생 화면에는 정답이 가지 않는다.

> 상태(2026-10-31): **090a~m 과 096a~h(프로젝트 확장) 모두 운영 DB에 적용·확인했다.** 090 은 2026-10-31 이전에 적용됐고(운영에서 표 5개·함수 확인), 096 은 2026-10-31 에 적용 후 `096_check.sql` 항목을 모두 확인했다. 아래 "SQL 적용 순서"는 새 환경용 기록이다.

## 선생님 흐름
1. **내 단어장**의 단어장 줄 "단어암기숙제"(단어 4개 이상, 숙제 기능이 열린 학원) 또는 **초등 800 단어장** 화면의 "단어암기숙제"(레벨 선택 후).
2. 배정 창(`WordMemoryAssignModal`): 자료 → 반·학생 → 하루 학습량(가볍게/보통) → **미리보기**(단어 수, 새 단어를 모두 만나는 데 걸리는 날, 쓸 수 있는 활동과 못 만드는 이유) → "배정하기".
   - 추가 설정(선택): 숙제 이름, 새 단어 소개 기간(7~60일), 그 뒤 복습 기간(0~30일).
   - 하루 학습량: 가볍게 = 문제 최대 12 · 새 단어 3 · 약 3~6분 / 보통 = 최대 20 · 5 · 약 5~10분. 시간은 어림이며 화면에도 그렇게 쓴다.
   - 배정 전에는 아무것도 만들지 않는다. 창을 열 때 요청 번호(`requestId`)를 정해 두 번 눌러도 한 번만 배정된다.
3. 배정 후 학생별 개인 링크(`/wm/:열쇠`)와 복사 단추. **숙제 페이지**(`/homework`) 위쪽 "단어암기숙제 현황"에서 계획별로 열어 본다.
4. 학생 포털(`/s`) 홈에도 링크가 뜬다(`wm_student_links`, 포털 로그인 열쇠로만).

## 학생 흐름 (`/wm/:열쇠`, 로그인 없음)
- 시작 화면: 복습할 단어 / 아직 어려운 단어 / 새로 배울 단어, "오늘의 단어암기숙제 시작"(중간에 나갔다 오면 "이어서 하기" + 남은 문제 수). 기록이 없는 첫날은 "처음에는 모두 같은 단어로 시작해요"라고 알린다(근거 없는 개인화 주장 안 함).
- 새 단어는 소개 카드(단어·뜻·그림·발음·예문, "알았어요") → 몇 문제 뒤 알아보기 → 더 뒤 다른 활동으로 한 번 더.
- 틀리면 정답을 보여 주고 3문제쯤 뒤에 **다른 활동**으로 한 번만 다시 묻는다(하루 다시 묻기 상한 안에서). 도움말: 고르기는 보기 하나 지우기, 철자는 첫 글자, 배열은 첫 조각 — 쓰면 그 문제는 "도움 받음"으로 기록된다.
- 하루가 끝나면 "오늘은 여기까지", 내일 이어서 할 복습 수·아직 안 만난 새 단어 수·다음 복습 날짜. 기간이 끝나면 종료 화면과 단어 수집장.
- **단어 수집장**: 단계는 아이콘+글자로 구분(색만으로 안 함). 아직 안 만난 단어는 칸만 보이고 낱말·뜻을 미리 보내지 않는다.

## 규칙 (wm-v1, 서버 SQL)
- **하루 문항 상한**: 가볍게 12 / 보통 20(그중 틀린 낱말 다시 묻기 몫 2 / 4). 복습은 본 문항의 70%까지만, 나머지는 다음 날로 남는다 → 며칠 쉬어도 밀린 학습이 무제한으로 쌓이지 않는다.
- **복습 우선순위**: 틀린 적 있는(어려운) 낱말 → 오래 밀린 순. **새 낱말**은 공부 기간 안에서만, 하루 3/5개 이하, 복습이 많으면 줄이고(70% 초과면 0).
- **활동 사다리**(도움 없이 처음 답으로 맞힌 횟수에 따라 단서를 줄인다): 그림/뜻 → 뜻→단어·듣고 고르기 → 글자 배열·문장 빈칸 → 철자 입력 → 듣고 쓰기. 최근 틀린 능력(뜻·철자·듣기·문장·그림)이 있으면 그 능력을 연습하는 활동으로, 며칠 연속 틀린 단어는 한 칸 쉬운 활동부터. 같은 활동을 연달아 쓰지 않는다.
- **숙련 판정**(많이 눌렀다·오래 했다로 완료시키지 않는다): 0 처음 만남(소개 카드) → 1 연습 중(문제를 풀어 봄) → 2 **혼자 맞힘**(소개한 날 *이후*, 도움 없이, 처음 답으로 맞힘) → 3 **며칠 뒤에도 기억함**(서로 다른 두 날 위 조건을 만족하고 두 날이 2일 이상 떨어짐). 소개 당일에 맞힌 것·도움 받은 것·다시 풀기는 기억 증거로 세지 않는다. 틀려도 단계는 내리지 않고 "다시 확인해요"로 표시.
- **다음 복습일**: 연속 성공 1회 +2일, 2회 +4일, 3회 +7일, 4회 이상 +14일. 틀림·도움·다시 풀기는 +1일. 날짜는 한국 시간 기준이고 "경과일"로 계산한다(실제 학습일만 세지 않는다). 결석해도 날짜가 지났다고 일정이 앞당겨지지 않고 상한만 지킨다.
- 특정 간격이 모든 학생에게 최적이라고 주장하지 않는다. 규칙 버전은 `wm_plans.rule_version`(wm-v1)에 기록.

## 원본·기록 보호 / 권한 / 중복
- **배정 시점 스냅샷**: `wm_plans.cards`(낱말·뜻·품사·그림 주소·예문). 원본 단어장을 고치거나 지워도 배정된 숙제는 그대로다. 학생 기록은 `wm_words`(학생×낱말), 하루 학습은 `wm_sessions`, 답은 `wm_answers`(추가만).
- **같은 철자·다른 뜻**: 열쇠 = `낱말|뜻`(소문자·공백 정리). bank(은행)·bank(둑)은 별도 기록이고, 서로 보기에 섞이지 않는다.
- **재배정**: 같은 학생이 같은 낱말·뜻을 예전에 만났으면 "이어받음"으로 표시하고 단계 0·혼자 맞힘 0으로 시작한다(다시 확인 대상). 이미 외웠다고 판정하지 않는다.
- **권한**: 다섯 표는 RLS 정책이 없고 `anon/authenticated` 권한도 회수해 직접 읽기·쓰기가 막혀 있다. 모든 접근은 security definer 함수로만: 학생 함수는 개인 링크 열쇠가 있어야 하고(학원·기능·보관·닫힘 확인), 선생님 함수는 직원+같은 학원+`homework` 기능이 열려 있어야 한다. 내부 함수는 아무도 직접 못 부른다.
- **중복 방지**: 배정은 요청 번호로 멱등(재시도 시 빠진 학생만 추가), 같은 단어 묶음을 진행 중인 학생은 건너뜀. 답은 문제 하나에 한 번(처음 답만), 같은 요청 번호(`client_id`)는 처음 결과 그대로. 전송 실패 시 화면의 "다시 시도"가 같은 번호를 다시 보낸다.
- 기존 숙제·스탯·학습 기록(`learning_events`, 스탯 산식)은 **바꾸지 않았다**. 단어암기 기록은 따로 쌓이며 기존 스탯 카드에는 아직 연결하지 않았다.
- 시각 조작: `app.wm_now`(DB 설정)는 테스트 전용이며 클라이언트가 바꿀 수 없다(`wm_now()`).

## 남은 제약·미검증
- **운영 Supabase(PostgREST·실제 anon/authenticated 역할)에서는 아직 실행하지 않았다.** 로컬 PGlite 에서 권한을 `has_*_privilege`로 확인했을 뿐이다. 적용 후 `090_check.sql` 과 학생 링크 한 건으로 확인할 것.
- 복습 간격·숙련 기준은 단순하고 설명 가능한 규칙이지 학습 효과를 검증한 값이 아니다(운영 데이터를 보고 조정할 자리: `wm_apply_result`, `wm_pick_styles`, `wm_mode_params`).
- 예상 시간(15~30초/문항)은 어림이다.
- 한 번에 한 반만 배정한다. 반이 다른 학생을 섞거나 단어를 400개 넘게 배정할 수 없다. 학생이 같은 단어 묶음을 진행 중이면 중복 배정은 건너뛴다.
- 단어 수집장은 기존 그림·아이콘만 쓴다(새 캐릭터·이미지 없음). 기존 학생 스탯 카드·학부모 리포트에는 단어암기 기록을 아직 연결하지 않았다.
- 숙제 기능(`homework`)이 닫힌 학원에서는 배정·학생 입장 모두 막힌다(기본값이 닫힘이라 열려 있어야 쓴다).
- 파닉스·문법·게임 규칙은 건드리지 않았다. Safari·실기기 터치 키보드는 확인하지 않았다(Chromium 모바일 에뮬레이션만).

## 프로젝트 확장 (2026-10-31, `supabase/096a~h` → `096_check.sql`, 되돌리기 `096_rollback.sql`)
초등 800 같은 큰 범위를 **정해진 기한까지 외우는 프로젝트**로 쓰도록 090 위에 더했다(090 은 그대로, 함수는 `create or replace` 로 확장).
- **규모(096a·b)**: 낱말 최대 **1000개**(전엔 400), 공부 기간 최대 240일·복습 기간 최대 90일, 하루 분량 **plus**(문항 30·새 낱말 10·다시 묻기 5). 앱 `plan.ts` 와 서버 `wm_mode_params` 가 같은 숫자.
- **새 방식(096d·e)**: 사다리 칸마다 새 방식을 끼워 며칠에 걸쳐 돌려 만난다 — 따라 쓰기(copy)·힌트 글자(hint)·그림 쓰기(typepic)·섬광(flash)·점점 가리기(fade)·맞다/아니다(ox)·헷갈리는 짝(confuse, 철자 비슷한 순)·두더지(whack)·괴물(monster)·풍선(balloon)·낚시(fish). 기존 사다리의 첫 후보와 "틀린 능력 먼저" 규칙은 그대로. 학생 화면은 숙제 블록과 같은 `QuestionCard` 를 쓴다(새 학생 화면 코드 없음).
- **학생별 조정(096a·c·e·g)**: `wm_targets.mode_override`(분량)·`focus_skill`(철자/듣기/뜻/문장 속 쓰임 집중) — 하루 학습을 만들 때(`wm_build_session`)와 방식을 고를 때(`wm_pick_styles`) 따른다. 지금 틀린 능력이 있으면 그것이 집중 설정보다 먼저.
- **아침 브리핑(096f)**: `wm_plan_briefing` — 어제 끝냄/하는 중/안 함, 연속 학습일, 오늘 복습 수, 이번 주 반이 가장 헷갈린 낱말 10개(수업 3분 확인·확인 숙제로 연결).
- **다음 단계 카드(096g)**: `wm_plan_steps` 가 규칙(AI 아님)으로 제안 — 3일 넘게 안 함→분량 줄이기 / 정답률 60% 미만(20문제 이상)→줄이기 / 5일 이상·정답률 90% 이상(40문제 이상)→늘리기 / 한 능력이 틀림의 40% 이상(3번 이상)→그 능력 집중 / 집중 중인데 그 능력 틀림이 2번 미만→끝내기. **선생님이 `wm_apply_step` 으로 승인해야만** 바뀌고(자동 변경 없음), 바꾼 내용은 `wm_step_log`(표는 누구도 직접 못 읽음)에 남는다.
- **진행·졸업·페이스(096h)**: `wm_plan_progress` — 구간(50개씩)별 졸업(낱말 상태 3) 수, 졸업 95% 이상이면 **완성**, 지금 속도(졸업 수 / 지난 날)로 완성 예상일·마감 안인지(기록 2일 미만이면 null). `wm_plan_cards`(번호 범위)·`wm_plan_weak_cards`(졸업 못 한 낱말) 는 시험용.
