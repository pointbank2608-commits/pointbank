# 게임 시작·전체화면·선택적 이름 개편 (2026-10-20)

## 상태와 기존 구현

요청 시작 시 main의 77550f7 및 다른 작업의 새 게임 미커밋 변경이 있었다. 작업 중 9de9753 커밋이 추가됐으며 다른 작업의 내용과 커밋을 되돌리지 않았다. 구현 검증 후 사용자의 별도 요청에 따라 코드 커밋·푸시·Vercel 배포를 진행한다. 운영 SQL은 실행하지 않는다.

기존 홈의 게임/활동지 → 자료 생성 → 추천 → 최근 실제 자료 → 내 수업 위계, 전체 게임 목록 진입, 내 단어·문장의 생성/필터/그룹/이전 버전, 기존 항목 편집기, 계정·학원별 임시 보존, 자료·활동지·수업 연결은 재사용했다. 중복 편집 데이터 모델이나 대규모 데이터 마이그레이션을 만들지 않았다.

## 이번 변경

- 주 시작 버튼은 실제 미리보기 중앙의 큰 ▶ 게임 시작 하나다. 우상단 시작 버튼을 제거했다. 실제 native items/config에 따른 항목·문장·문제·팀 수와 준비 여부를 표시한다. 임의 숫자를 넣지 않으며, 타이머 연습처럼 외부에서 현재 참여 모드를 알 수 없는 경우 참가자 수를 추측하지 않는다. 미완성 항목은 이유와 기존 편집기로 연결한다.
- 편집 패널의 확인은 '이 내용으로 준비하기' 또는 '자료 저장하고 준비하기'다. 내용을 적용해 준비한 뒤 중앙에서 실제로 실행하므로 저장과 실행이 혼동되지 않는다. '샘플로 바로 해보기'는 새 샘플 임시 구성의 반영을 기다렸다가 실행한다. 자료·수업은 자동 저장하지 않는다.
- 전체화면은 크기만 바꾼다. 일반/네이티브 전체화면/권한 거절 시 대체 전체화면 모두 시작 전 중앙 버튼이 유지된다. 전체화면 동안 오른쪽 위에 종료 버튼이 항상 있다. 관리 도구는 메뉴로 접고 게임 공간을 확보한다. 버튼·Escape·브라우저 종료는 같은 판/문제/점수/실행 상태를 유지하며 게임 목록으로 이동하지 않는다. 전체화면 상태는 fullscreenchange로 동기화한다.
- '☰ 메뉴'와 패널 제목 '메뉴'로 통일했다. 계속하기는 패널 닫기, 게임 설정·수정은 기존 편집기 직접 열기, 준비 화면으로는 같은 게임의 준비, 다른 게임 고르기는 전체 목록이다. 같은 자료로 다른 게임 하기/활동지 만들기/수업 추가는 별도 재사용 행동으로 유지한다.
- 이름은 선택이다. 공통 API의 게임 구성·단어장·문장 모음 생성은 빈 값/공백/생략에 유형을 알 수 있는 기본 이름을 쓴다. 같은 범위의 기존 이름을 확인해 2, 3을 붙인다. 직접 입력한 이름은 유지하며 placeholder 예문을 저장하지 않는다. 공개 범위·권한은 변경하지 않는다. 공통 패널에서 기존 rename 핸들러로 이름을 바꿀 수 있다. 수업 추가에서도 새 수업 선택 후 이름을 비우면 기본 수업 이름을 쓴다. 기존 수업 편집기의 별도 규칙은 변경하지 않았다.
- 방법 영상은 설명용이며 길이는 실제 loadedmetadata의 duration으로 표시한다. 확인 전에는 길이를 표시하지 않는다. 다섯 기존 MP4를 재사용한다. 영상 오류 안내가 있으며 패널을 닫으면 재생을 멈춘다. 아이스크림 단계는 '1. 메뉴판 보기'로 변경했다.
- 기존 sentence 데이터 분류를 사용해 게임 목록에 문장 그룹/필터를 제공한다. 번개 피하기만 category=sentence, moment=practice로 바꾸고 문장 잡기 직후로 이동했다. 관련 문장 게임의 목록 표시를 일관되게 묶되 수업 구성에서 쓰는 다른 게임의 원래 moment 값은 유지한다. 개수·검색·필터·카드 순서는 같은 그룹 함수에서 계산한다.
- 오래된 '메뉴는 5개예요', 게임 실행 전 반을 고르라는 안내, 고정 15초 영상 문구 등을 현재 흐름에 맞췄다. 한국어·영어를 함께 반영했다.
- 모바일 일반 화면으로 돌아올 때 이전 데스크톱 측정 폭을 버려 게임이 과도하게 커지거나 잘리지 않게 했다. 원래 일러스트·점토 게임 UI·학습 규칙·점수 계산을 보존한다.

## 공통 적용과 예외

현재 저장소 53개 교사 게임은 공통 GameWorkspace/GameThemeFrame을 사용하며 기존 설정을 열고 닫는 회귀 검증을 통과했다. 새 이미지 에셋은 필요하지 않았다.

- 원래 자동 팀 차례·동시 참여·전체 활동에는 공통 수동 차례를 새로 강제하지 않는다. 기존 수동 순서 게임만 현재/다음·제외·순환을 유지한다.
- 타이머·내장 역할극·가게·수학·전용 다이어그램/문장 성분/스토리 게임은 원래 준비 방식을 유지한다.
- 스토리 게임 3개는 기존 전용 편집/저장과 문항 규칙을 보존하면서 중복된 내부 전체화면 도구를 공통 메뉴에 연결했다. 준비로 돌아가는 동작은 명시적 다시하기와 분리했다. 세 게임의 실제 카드 조작과 설정/준비 복귀 시 동일 DOM·진행 보존을 확인했다.
- 학생 읽기 전용 게임에는 교사 준비 UI를 씌우지 않는다. 기존 저장 게임의 학생 실행과 생성 버튼 부재를 확인했다. 별도 학생 개별수업 전체 흐름을 재검증한 것은 아니다.
- 수업 발표는 기존 수업 진행바/전체화면 체계를 유지한다. 저장 수업 게임 교체·뒤 활동·따라보기 snapshot 호환성을 확인했다.
- 실시간 퀴즈쇼는 서버 세션을 메뉴와 함께 임의로 중지하지 않는다. 임시 활동의 교실 시연과 제약 안내를 확인했으며 다기기 온라인 대회는 미검증이다.

## 서버 이름 기본값

프런트엔드의 공통 생성 API는 항상 유효한 이름을 보낸다. DB 직접 요청의 빈 이름에도 같은 원칙을 적용하는 선택적 서버 변경은 `supabase/089_optional_activity_names.sql`과 읽기 전용 `089_check.sql`에 있다. 기존 066 kind 필드가 있는 스키마를 전제로 한다.

089는 빈 이름의 insert/명시적 name update에만 기본값을 정한다. 기존 행 일괄 변경·RLS/권한 변경·공개 범위 변경은 없다. SECURITY INVOKER와 academy/class 범위의 advisory transaction lock을 사용한다. 실제 제목은 식별자가 아니며 사용자가 명시한 같은 제목을 강제로 바꾸지 않는다.

089는 로컬 PGlite PostgreSQL의 최소 테이블과 역할/RLS 정책에서 검증했으며 **운영에는 적용하지 않았다**. 운영의 실제 전체 스키마·기존 트리거·RLS 조합은 미검증이다. 운영 SQL을 적용하기 전에는 DB 직접 blank insert의 서버 기본값을 사용 중이라고 볼 수 없다. 기존 프런트엔드 생성 경로는 API에서 이름을 채우므로 이 SQL 없이도 작동한다.

- `check-workspace.mjs`: 현재 53개 설정 열기/닫기 및 실행 오류 없음, 기존 반/명단 제외와 수업 발표의 다음 활동·따라보기 유지.
- `check-preparation-play.mjs`: 기존 항목 편집기, 원본 저장 실패/재시도/중복 클릭, 자료 재사용, 임시 팀/순서 현재·다음/순환/한 명 경계, 틱택토 실제 수/원래 차례, 타이머 START/STOP/결과, 퀴즈쇼 교실 미리보기, 긴 문장 24개 내부 스크롤, 작성 전 텍스트·종류 전환·목록 왕복 복구를 확인했다.
- `check-quick-activity.mjs`: 저장/다시 열기, 활동지 전달, 명시적 새 수업/기존 수업 추가, 반 없는 저장 수업 실행, 홈/자료 관리의 desktop/tablet/mobile 검증.

- `check-quick-integrity.mjs`, `check-workspace-logic.mjs`: 원본 불변·계정/학원/로그아웃 차단·임시 수정 DB 미접근·반복 보존 제한·이전 수업 변환·동시 편집 거부·원래 자료 변환·시계 pause/resume 검증.

53개 모든 게임의 완주/점수 계산을 전수 검증한 것은 아니다. 실제 운영 계정/결제 플랜 조합, 운영 RLS, 실제 전자칠판/Safari 기기, 다기기 온라인 세션은 미검증이다. 작성 내용/설정은 임시 복구하지만 새로고침 후 진행 중 점수·물리 상태까지 영구 복구하지 않는다. 긴 문장은 내부 스크롤을 사용할 수 있다.
