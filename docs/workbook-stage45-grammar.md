# 파닉스 4·5단계와 문법 워크북

2026-10-23. 구현·검증 후 사용자가 커밋·푸시·운영 배포를 승인했다. 워크북 변경만 선별해 main에 반영하며 Vercel 자동 배포를 확인한다. 기존 작업 중 변경을 보존했으며 추가 SQL은 없다.

## 사용 경로

- 활동지(인쇄) → 파닉스 4단계 워크북: `/materials/phonics-stage-4-workbook`
- 활동지(인쇄) → 파닉스 5단계 워크북: `/materials/phonics-stage-5-workbook`
- 자료 → 문법 → 칠판 아래 **워크북 만들기**: `/materials/grammar-workbook?topic=third-s`
- 활동지(인쇄) → 기타 자료 → 문법 기본 연습과 활동 미션에서도 같은 페이지에 접근한다.

유닛 선택·전체 선택·선택 지우기·선택 유닛 인쇄를 제공한다. 워크북 설정 UI는 한국어·영어 전환을 지원한다. 학생에게 인쇄되는 문법 설명·지시문은 검수한 한국어 교육 콘텐츠다.

## 파닉스 원본과 유닛

실제 로그인된 `/phonics` 화면에서 2026-10-23 규칙·단어·강조 구간·그림 연결을 확인했다. 운영 코드는 기존 `fetchPhonicsBank()`로 같은 `phonics_bank`를 읽는다. 정적 임의 단어 목록을 운영용으로 추가하지 않았다. `scripts/workbooks/observed-bank.mjs`는 원본 화면을 전사한 검증 전용 자료이며 가짜 ID만 쓴다.

| 단계 | 원본 규칙 | 학습 항목 | 서로 다른 단어 | 구성 유닛 | 인쇄 가능한 유닛 | 인쇄 쪽수 |
|---|---:|---:|---:|---:|---:|---:|
| 4 | 24 | 68 | 67 | 30 | 29 | 58 |
| 5 | 17 | 58 | 58 | 27 | 27 | 54 |

4단계의 `brush`는 br와 sh를 각각 배우므로 원본처럼 두 항목으로 유지한다. 목표 위치는 각각 `[0,1]`, `[3,4]`다. 유닛의 단어가 원본에서 빠지거나 잘못 추가되지 않았는지 원본 항목 ID 전체와 비교한다.

- 같은 원본 규칙 안에서 2~3개씩 묶는다. 네 단어는 2+2로 분리한다.
- SH 1유닛은 확정 샘플의 `ship · shell · fish`. 나머지 `shop · dish · brush`도 빠짐없이 별도 유닛에 들어간다.
- 5단계 `oo (short)` / `oo (long)`과 `ow (long o)` / `ow (diphthong)`은 원본 규칙 이름 전체를 키로 사용해 합쳐지지 않는다.
- **미완성은 4단계 21유닛 `Final Blend (lk): milk` 하나**다. 원본에 단어가 하나뿐이라 2~3단어 유닛으로 만들 수 없다. 단어를 임의로 추가하거나 다른 목표 규칙과 합치지 않았다. 선택을 막고 ‘준비 중’과 이유를 표시한다.

## 기존 워크북 재사용

`CvcWorkbookSheets.tsx`의 같은 두 페이지 렌더러와 `TracingRow`를 사용한다. CVC·장모음 데이터와 기존 강조·노란 빈칸 상자 동작은 유지했다. 새 단계는 유닛별 제목·그림·선화·목표 위치만 전달한다.

콘텐츠 폭 186mm, A4 여백 12mm, Fredoka 제목·Andika 낱말/따라 쓰기, 파스텔 번호·활동 제목·테두리, 노란 유닛 머리글과 카드, 기존 가이드·점선·활동 고정 높이(64/66/56, 60/66/66mm)를 유지한다. Complete the Word는 50×57mm 큰 그림 카드를 가로로 놓고, 여러 글자로 된 목표는 하나의 연속 밑줄로 비운다. SH 전체를 빨간색으로 표시하며 fish의 끝 sh도 처리한다. 긴 단어에만 낱말 글꼴 크기와 읽기 행의 단어 칸을 조정해 카드 크기는 유지한다.

기존 CVC·장모음 각 두 페이지를 수정 전후 같은 배율로 렌더링해 **픽셀 차이 0**을 확인했다. 실제 앱 인쇄에는 숨겨진 사이드바의 왼쪽 여백이 남아 축소되던 문제가 있어, 다섯 워크북 경로에서만 인쇄 레이아웃의 여백을 해제했다. 기존 학원 워터마크 설정과 작은 브랜드 푸터는 유지한다. 검증용 실제 앱 PDF는 기존 설정으로 워터마크를 끈 상태다.

## 그림

컬러 그림과 기존 선화는 보존했다. 부족한 실제 색칠 선화 47개는 내장 `image_gen`으로 개별 생성하고 흰 배경·검은 윤곽·빈 색칠 영역·의미를 육안 확인했다. 사진의 흑백 필터나 이모지를 사용하지 않는다. 결과는 `app/public/word-bank-lineart/<word>.webp`에 저장했다. 전체 대상과 프롬프트는 `app/scripts/workbooks/lineart-generation.json`에 있다.

dev/build 전 기존 `lineart-manifest.mjs`가 실제 선화와 컬러 그림 목록을 만든다. 원본 그림 또는 목표 구간이 부족하면 해당 유닛의 인쇄를 막는다. HTTP 이미지 로드 실패 시에도 이유를 표시하고 선택 자료의 인쇄를 막는다. 이번 검증 자료에는 누락된 컬러 그림·선화가 없다.

## 문법

실제 지원 주제는 **3인칭 단수 현재형 -s/-es/have→has** 하나다. 다른 문법을 고르면 ‘준비 중’을 표시하고 같은 문제를 복사하지 않는다.

- 기본 연습: 동사 고르기 5 + 빈칸 5 + 오류 수정 3. I/You/We/They와 He/She/It/단수 명사를 섞고 의문·부정문은 넣지 않았다.
- 로봇 탐정: 사용자 제공 BIBI/MOMO/TOBI/KIKI 소개 카드, 네 I 단서 → He 문장, 소포 주인 찾기, 소리 내어 말하기. 정답은 likes / watches / goes / has, 주인은 TOBI다.
- 학생 기본/미션 각 한 쪽, 교사용 정답·풀이/미션 설명·말하기 예시 각 한 쪽. 학생용만 기본 선택한다.
- 제목은 자동 생성하며 수정은 선택이다. 반·학생 등록·저장이 필요 없다. 기본/미션/함께와 학생/교사 자료를 고를 수 있다.
- `grammarWorkbook.ts`에 검수 문항·정답·풀이·미션 자료를 두고 공통 인쇄 셸·연습 블록을 재사용한다. 기존 문법의 내 단어장 예문 생성은 품사 기반이지만 워크북의 13문항과 추리의 유일 정답을 보장하는 검증이 없어 자동으로 섞지 않는다.
